## 二、核心模块详解

### 2.1 FT_file_parser.py — FT 文件解析

**职责：** 检测文件格式 → 读取数据 → 提取元数据（单位/限值）→ 单位换算 → 过滤 → 缓存

#### 类：`FTData(path, config_path, force_reparse=False)`

**构造参数：**
- `path : str | Path` — 数据文件路径（CSV/TXT/DAT）
- `config_path : str | Path` — 格式签名配置（`config/ft_data_config.toml`）
- `force_reparse : bool` — 跳过缓存强制重新解析

**主要属性：**

| 属性 | 类型 | 说明 |
|------|------|------|
| `data` | `pd.DataFrame` | 纯数据部分（不含 Unit/LL/HL 三行 meta），测试列 float64 |
| `raw_df` | `pd.DataFrame` | 完整 DataFrame（含 3 行 meta + 数据行），测试列 object |
| `test_columns` | `list[str]` | 解析时确定的测试列名（由 pre_test_columns 决定边界） |
| `meta_columns` | `list[str]` | 解析时确定的元数据列名（PART_ID, SOFT_BIN 等） |
| `units` | `dict[str, str]` | 每列的 SI 单位（如 "A", "V", "Ω"） |
| `lower_limits` | `dict[str, float]` | 每列的下限值 |
| `higher_limits` | `dict[str, float]` | 每列的上限值 |
| `path` | `Path` | 文件路径 |

**解析流程（`_parse()`）：**

```
1. _detect_format()
   → 遍历 config 中的 signatures
   → 对每个 signature，逐行扫描文件，检查 header_identifiers
   → 匹配标识符最多的 signature 胜出
   → 返回 {sig, header_row, header_cols, data_start, encoding, delimiter}

2. 列名处理
   → 合并 part_id 行和 data_col_header 行（如果偏移不同）
   → 应用 column_map 重命名
   → 用 pre_test_columns 确定测试列起始位置（找最后一个匹配列）
   → 拆分为 meta_header + test_header

3. 构建 DataFrame
   → 从原始行读取 meta 行（Unit/LL/HL）
   → 从 data_start 开始读取数据行（stop_at_blank_row 控制停止）
   → pd.DataFrame(all_rows, columns=all_cols)
   → idx 0-2: Unit/LL/HL meta 行，idx 3+: 数据行

4. _extract_meta_rows()
   → 从第 0 行提取单位
   → 从第 1 行提取下限
   → 从第 2 行提取上限
   → 跳过 meta_header 中的列

5. _apply_unit_conversion()（向量化）
   → 对每个非 meta 列：
     → pd.to_numeric(数据切片, errors="coerce")
     → 如果有单位：UnitConverter.parse_unit() 获取乘数
       → callable: apply(multiplier)
       → 数值乘数: * multiplier
     → 写回 DataFrame

6. _filter_rows()
   → 跳过 skip_row_values 匹配的行（如 PART_ID=1/END）
   → 遇到全空行停止
   → 列名匹配大小写不敏感

7. _validate()
   → 检查 DataFrame 非空
   → 检查 PART_ID 列存在
   → 检查至少有 1 个测试列
   → 检查至少有 4 行（3 meta + 1 数据）
```

**格式检测算法（`_detect_format()`）：**

```python
for enc in encodings:
    text = read_text(encoding=enc)
    for sig in signatures:
        for row_idx, line in enumerate(lines):
            cells = line.split(delimiter)
            upper_cols = {c.upper() for c in cells if c.strip()}
            if all(identifier in upper_cols for identifier in sig.identifiers):
                best = match  # 标识符数多的优先，同数靠前的优先
                break  # 找到匹配就跳出内层循环
```

**关于 `data` 属性：**

`data` 返回 `self._df.iloc[3:].reset_index(drop=True)` 再做 `astype(float)`。
前 3 行（Unit/LL/HL）被切掉，测试列转为 float64，meta 列保持 object。

> ⚠️ `data` 与 `raw_df` 的区别：`raw_df` 包含 meta 行且所有列均为 object
>（因为前 3 行有字符串），`data` 是纯数值视图。

### 2.2 ft_cache.py — 三层缓存系统

**文件：** `core/ft_cache.py`

#### 类：`FTCache`（单例 `ft_cache`）

**三层缓存结构：**

```
FTData.__init__(path, config)
  → ① 内存 LRU（OrderedDict, max 100 条）
    → ② SQLite（index.db 记录索引 + cache 状态）
      → ③ 全量解析
```

**默认缓存路径：** `%PROGRAM_DIR%/cache`
- `%PROGRAM_DIR%` 在运行时解析为程序目录
- Linux 开发：项目根目录/cache
- 打包后：exe 所在目录/cache

**公共 API：**

```python
# 获取缓存（返回 state dict 或 None）
state = ft_cache.get(file_path)

# 写入缓存
ft_cache.put(file_path, {"_df": df, "_units": {...}, ...})

# 快速获取元数据（不加载 DataFrame）
meta = ft_cache.get_meta(file_path)
# → {signature_id, test_columns, meta_columns, row_count, col_count, ...}

# 按测试列名搜索
results = ft_cache.search_by_columns("IDSS")
# → [{file_path, test_columns, row_count, ...}, ...]

# 运行时切换缓存目录
ft_cache.set_cache_dir("/new/cache/path")

# 清空全部缓存
ft_cache.clear_all()

# 强制重新解析（绕过缓存）
FTData(path, config, force_reparse=True)
```

**缓存 key：** 使用文件绝对路径 + `file_size` + `file_mtime`。
文件被修改 → 自动失效 → 下次读会重新解析。

**SQLite 表结构：**

```sql
CREATE TABLE file_cache (
    file_path       TEXT PRIMARY KEY,
    file_size       INTEGER NOT NULL,
    file_mtime      REAL NOT NULL,
    signature_id    TEXT,
    test_columns    TEXT,      -- JSON 数组逗号分隔
    meta_columns    TEXT,
    row_count       INTEGER,
    col_count       INTEGER,
    pickle_path     TEXT,
    cached_at       REAL NOT NULL,
    access_count    INTEGER DEFAULT 0
);
```

**Pickle 存储内容（`_dump_state()`）：**

```python
{
    "_df": DataFrame,           # 完整 DataFrame
    "_units": dict,             # 单位映射
    "_lower_limits": dict,      # 下限
    "_higher_limits": dict,     # 上限
    "_meta_header": list,       # meta 列名
    "_test_header": list,       # 测试列名
    "_fmt": dict,               # 格式检测结果
    "_config": dict,            # 配置（避免重新加载文件）
}
```

### 2.3 data_merge.py — 数据合并

**职责：** 读取 T0/TX 文件 → 合并为一张大表 → 处理冲突

#### 函数：`merge_t0_tx(t0_paths, tx_paths, ...)`

**参数：**
- `t0_paths : list[str]` — T0 文件路径列表
- `tx_paths : list[str]` — TX 文件路径列表
- `tx_group_map : dict[str, str]` — 文件名→分组名映射
- `on_conflict : callable` — 冲突处理回调
- `config_path : str | None` — 传给 FTData 的配置路径

**流程：**
```
读取 T0 文件（逐个 FTData）
  → 每行标记 group="T0"
读取 TX 文件（逐个 FTData）
  → 按 tx_group_map 设置 group 名
  → 按 SN 分组（如果配置了 sn_map）
按 (PART_ID, group) 分组
组内横向合并
  → 同列多个不同值 → 收集冲突（通过回调让 UI 弹窗）
返回合并后的 DataFrame
```

> ⚠️ T0 和 TX 读取失败时静默跳过（`except FTParseError: continue`），
> 目前不会通知用户。改进方向：收集错误列表返回给调用方。

### 2.4 unit_converter.py — 单位换算

**类：`UnitConverter`**

```python
# 解析单位字符串 → (SI单位, 乘数)
UnitConverter.parse_unit("mA")     # → ("A", 0.001)
UnitConverter.parse_unit("uA")     # → ("A", 1e-06)
UnitConverter.parse_unit("kV")     # → ("V", 1000.0)
UnitConverter.parse_unit("°F")     # → ("°C", <function>)
UnitConverter.parse_unit("mOhm")   # → ("Ω", 0.001)

# 转换值
UnitConverter.convert(50, "uA")    # → (5e-05, "A")

# 显示单位
UnitConverter.normalize_unit_display("mA")  # → "A"
```

支持的单位前缀：p, n, u, m, k, M, G
支持的特殊单位：°F（函数映射 °F→°C）

## 三、格式签名配置

**文件：** `config/ft_data_config.toml`

每个 `[[signatures]]` 块定义一种文件格式：

| 字段 | 类型 | 说明 |
|------|------|------|
| `format_id` | string | 签名唯一标识 |
| `header_identifiers` | string[] | 标识列名列表，全部匹配才算命中（匹配越多优先级越高） |
| `part_id_offset` | int | PART_ID 所在行相对于 header_row 的偏移（0=同一行） |
| `data_col_header_offset` | int | 测试列名所在行偏移 |
| `unit_offset` | int | 单位行偏移（-1=无单位行） |
| `lower_limit_offset` | int | 下限行偏移 |
| `higher_limit_offset` | int | 上限行偏移 |
| `data_start_offset` | int | 数据起始行偏移 |
| `pre_test_columns` | string[] | 预测试列名列表，最后一个匹配列之后的列都算测试列 |
| `stop_at_blank_row` | bool | 数据区遇到空行是否停止 |
| `delimiter` | string | 分隔符（逗号/制表符） |
| `encoding` | string | 文件编码 |
| `skip_row_values` | dict | 过滤条件，如 `{PART_ID: ["1", "END"]}` |
| `column_map` | dict | 列名映射，如 `{MODULE_ID: "PART_ID"}` |

### 内置签名

| 签名 | 适用格式 | 说明 |
|------|---------|------|
| `DEFAULT_FT_FILE` | 标准 4 行头 CSV | PART_ID + SOFT_BIN 标识，header 后第 4 行数据 |
| `DEFAULT_FT_FILE2` | 带 AC_IDSS_T1 的 CSV | 比 DEFAULT 多一个标识符，用于区分类似格式 |
| `STS8200_FT` | STS8200 测试机输出 | 含 ~30 行 log 头，SITE_NUM 标识，blank 行分隔 |

### 添加新格式

1. 编辑 `config/ft_data_config.toml` 添加 `[[signatures]]`
2. 同步更新 `FT_file_parser.py` 中的 `DEFAULT_CONFIG_TOML`（自动创建配置时的模板）
3. 确保 `header_identifiers` 能唯一标识该格式（更多标识符 = 更高优先级）
4. 运行 `pytest tests/test_FT_file_parser.py` 验证

**关键行为（`_fg_update_result`）：**

```python
# 用户前后追加的内容在刷新时保留
old_key = edit._fg_last_auto_key
if old_key and old_key in current_text:
    prefix = text_before_old_key
    suffix = text_after_old_key
    edit.setText(prefix + new_auto_key + suffix)
else:
    edit.setText(new_auto_key)  # 完全重写了就直接覆盖
edit._fg_last_auto_key = new_auto_key
```

## 八、关键设计决策记录

| # | 决策 | 背景 | 影响 |
|---|------|------|------|
| 1 | `config_path` 是必需参数 | 用户明确要求"config必须传入，不要给default参数" | 调用方必须提供配置路径 |
| 2 | 配置文件不存在时自动新建 | 方便首次使用 | 用 DEFAULT_CONFIG_TOML 模板创建 |
| 3 | `_detect_format` 自包含 | 用户要求不 import core 其他模块 | 直接读取 TOML 文件 |
| 4 | 标识符数量决定签名优先级 | 避免签名顺序耦合 | 列名越多匹配越精确 |
| 5 | `pre_test_columns` 找最后一个匹配 | 支持多个预测试列 | 前面的预测试列也会算作 meta |
| 6 | 列名大小写不敏感 | 不同测试机输出格式不一 | 所有列名比较都用 `.upper()` |
| 7 | 向量化 unit conversion | 逐格循环 50 万次太慢 | 8.3s → 0.5s（17x） |
| 8 | `test_columns` 由解析器动态确定 | 不依赖静态 META_COLUMNS 配置 | 更灵活，但 META_COLUMNS 可删除 |
| 9 | 三层缓存（内存→SQLite→解析） | 大文件重复解析太慢 | 缓存命中 0.3ms vs 解析 500ms |
| 10 | `--collect-all PySide6` | 避免 Qt 插件遗漏 | 增大包体积，但确保兼容性 |
| 11 | 去掉 PyInstaller `--splash` | 原生 splash 不支持文字 | 只用 Qt QSplashScreen |
| 12 | QLineEdit 前后缀保留 | 用户可在分组 key 前后追加内容 | 实现较复杂，需追踪 `_fg_last_auto_key` |

## 九、常见排查

### splash 不显示文字
- `QApplication` 必须在 `SplashModule.install()` 之前创建
- 调用后需要 `QApplication.processEvents()` 强制绘制

### 启动报错 "No module named 'PySide6'"
- 构建时加了 `--collect-all PySide6` 吗？
- 虚拟环境里装了 PySide6 吗？

### 文件解析失败
- 检查 `config/ft_data_config.toml` 中的 `header_identifiers` 是否匹配
- 检查文件编码（utf-8-sig vs gbk）
- 检查分隔符（逗号 vs 制表符）
- 用 `FTData(file, config, force_reparse=True)` 看具体错误

### 缓存不生效
- 缓存目录是否有写权限？
- 文件是否被修改了（mtime 变了）？
- `ft_cache.clear_all()` 可清空后重试

### SQLite 报 "cannot VACUUM from within a transaction"
- VACUUM 不能在事务内执行
- 已在代码中修复：单独开一个 connection 执行 VACUUM
